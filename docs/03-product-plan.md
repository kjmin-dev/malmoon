# Malmoon 제품 기획

> 기준일 2026-11-12. 근거는 [Smooth 분석](01-smooth-analysis.md)과 [시장과 미충족 니즈](02-market-and-needs.md)에 있다.

## 한 줄 정의

Malmoon은 여러 언어가 오가는 회의에서 듣고, 말하고, 마무리하는 것까지 돕는 실시간 코파일럿이다.
개인 경험은 Smooth와 같은 수준으로 맞추고, 차별화는 팀이 돈을 내는 이유 세 가지에 둔다.

## 핵심 가치

| 핵심 가치 | 뜻 | Smooth와의 차이 |
| --- | --- | --- |
| 어느 방향이든 | 한 회의 안에서 한국어와 영어가 섞여도 각자 자기 언어로 따라간다 | Smooth는 영어 회의만 번역하고 영어 방향으로만 통역한다 |
| 말하기까지 | 알아듣는 데서 끝내지 않고 발언하기까지 걸리는 시간을 줄인다 | Smooth의 말하기 지원은 읽는 답변 카드와 고가 음성 통역이다 |
| 떳떳하게 | 숨기지 않아도 되고 회사가 승인할 수 있다 | Smooth는 화면 공유 시 노출되고 여러 클라우드 벤더를 거친다 |

## 타깃

| 순위 | 사용자 | 여기서 시작하는 이유 |
| --- | --- | --- |
| 1 | 해외 고객, 본사, 지사와 주 1회 이상 회의하는 한국 기업의 5~50인 팀. 한국어 사용자와 비한국어 사용자가 섞여 있다 | 근거가 가장 분명한 두 틈(보안 심사, 영어 전용 제약)이 모두 팀 단위 문제다 |
| 2 | 영어 회의가 잦은 개인 직장인 | Smooth의 핵심 고객이다. 무료와 개인 요금제로 받아 팀 도입의 입구로 삼는다 |
| 3 | 보안 요건이 높은 대기업, 금융, 공공 | 기밀 경로가 성숙한 뒤에 공략한다 |

혼합 언어 팀의 수요는 아직 가정이다. 0단계 인터뷰에서 먼저 확인한다.

## 제품 원칙

1. 2초 안에 오지 않는 도움은 보여주지 않는다.
2. 숨기지 않고 분리한다. 화면 공유 중에는 보조 화면으로 옮기고, 스텔스 기능은 만들지 않는다.
3. 근거 없는 제안은 일반 표현이라고 표시한다.
4. 불확실한 자막은 불확실하다고 표시한다.
5. 데이터가 어디로 가는지는 사용자와 관리자가 고른다.

하지 않는 것: 면접과 시험용 숨김 모드, 회의에 들어가는 봇, 범용 회의록 도구와의 경쟁, 전화 통화 지원.

## 기능

### 동등 수준 기능

| 기능 | Smooth의 대응 기능 | 완료 기준 | 단계 |
| --- | --- | --- | --- |
| 봇 없는 캡처 | 시스템 오디오 청취 | Zoom, Meet, Teams에서 설정 없이 상대 음성과 내 음성을 따로 받는다 | 1 |
| 실시간 이중 자막 | 번역 자막 | 원문과 번역을 나란히 보여준다 | 1 |
| 실시간 프롬프터 | 현재 주제, 결정 요약, 답변 카드, 의도 칩, 질문창 | 질문이 끝나기 전에 답변 카드가 뜬다 | 1 |
| 사후 요약과 대화록 | 요약, 이중 언어 대화록, 노트 | 결정, 담당자별 액션 아이템, 남은 논의가 나온다 | 1 |
| 사전 준비 | 캘린더 기반 준비 화면 | 일정과 첨부 문서에서 발언 포인트와 예상 질문을 만든다 | 2 |
| 팀 메모리와 용어집 | Team 플랜 | 용어가 자막, 번역, 제안에 모두 반영된다 | 3 |
| 문장별 코칭과 리포트 | 대화록 리뷰, 표현 배우기, 점수 | 내 발화를 고쳐 주고 표현을 저장한다 | 3 |
| 본인 목소리 음성 통역 | Voice Pro | 가상 마이크로 회의 앱에 통역 음성을 보낸다 | 4 |
| 모바일 앱 | iOS, Android 앱 | 대면 회의 자막과 리포트 열람이 된다 | 4 |

### 차별화 기능

| 기능 | 푸는 니즈 | 동작 | 단계 |
| --- | --- | --- | --- |
| 신뢰도 표시와 개인 용어집 | 자막을 얼마나 믿을지 | 인식이 불확실한 단어를 흐리게 표시한다. 캘린더와 문서에서 이름과 약어를 자동으로 모은다 | 1 |
| 양방향 혼용 모드 | 영어가 아닌 회의, 섞이는 회의 | 발화 언어를 자동 감지해 듣는 사람의 언어로 보여준다. 한국어와 영어로 시작하고 일본어를 잇는다 | 2 |
| 말하기 사다리 | 듣기보다 어려운 말하기 | 네 단계로 돕는다. 발언권을 잡는 한 문장, 내 수준에 맞춘 짧은 답변, 한국어로 쓰면 영어로 바꿔 회의 채팅에 붙이기, 음성 통역 | 2 (음성 통역은 4) |
| 보조 화면 | 화면 공유 중의 보조 | 단축키 한 번으로 프롬프터를 휴대폰이나 두 번째 모니터로 옮긴다. QR로 연결하는 웹 화면에서 시작한다 | 2 |
| 데이터 경로 선택 | 회사 보안 심사 | 표준, 무보존, 기밀 세 경로를 둔다. 관리자가 팀 기본값을 정한다 | 3 (기밀은 4) |
| 관리 기능 | 회사 보안 심사 | SSO, 감사 로그, 저장 지역 선택, 참석자에게 보낼 안내 문구 템플릿 | 3 |
| 후속 조치 내보내기 | 회의 뒤 업무 연결 | 내가 약속한 일 목록과 확인 메일 초안을 만들고 Slack, Notion, Jira로 보낸다 | 3 |
| 줄어드는 도움 | 의존에서 성장으로 | 전체 번역, 어려운 표현만 주석, 끔 세 단계로 자막 양을 조절한다 | 4 (실험) |

후속 조치 내보내기와 줄어드는 도움은 수요 근거가 약하다. 인터뷰에서 수요가 확인될 때만 착수한다.

## 요금제 가설

음성 통역이 가격 차별화의 여지다. Smooth는 400분에 월 $50를 더 받아 분당 $0.125꼴이고, 우리 원가는 분당 $0.02~0.04다.

| 요금제 | 가격 가설 | 포함 |
| --- | --- | --- |
| Free | $0 | 가입 시 200분, 실시간 기능 전체, 개인 용어집 |
| Personal | 월 $19 | 무제한(공정 사용 한도), 음성 통역 월 120분 |
| Team | 좌석당 월 $29 | 팀 메모리, 공유 용어집, 무보존 경로, SSO, 내보내기 |
| Enterprise | 견적 | 기밀 경로, 감사 로그, 저장 지역 선택 |

## 로드맵

엔지니어 4명과 디자이너 1명을 가정한다. 16주에 동등 수준 알파, 36주에 팀 유료 출시가 목표다.
데스크톱 화면을 Rust로 직접 만드는 비용을 반영해 1단계와 2단계를 넉넉히 잡았다.

| 단계 | 기간 (누적) | 만드는 것 | 통과 기준 |
| --- | --- | --- | --- |
| 0. 검증 | 4주 (4주) | Smooth 유료 사용자 10명과 혼합 언어 팀 10곳 인터뷰. GPUI 오버레이, 지연, 인식 품질, 토큰 생성기 기술 검증 | 지연 목표를 실측으로 통과한다. 팀 5곳 이상이 도입 의향을 밝힌다 |
| 1. 동등 MVP | 12주 (16주) | macOS 데스크톱 앱: 캡처, 이중 자막, 프롬프터, 사후 요약, 신뢰도 표시. 디자인 시스템 기반. 로그인과 결제용 최소 웹 | 알파 사용자 50명. Smooth를 써 본 사용자 다수가 동급 이상이라고 평가한다 |
| 2. 차별화 | 10주 (26주) | 양방향 혼용 모드, 말하기 사다리, 보조 화면(웹), 사전 준비, Windows 앱 | 4주 차 주간 유지율 40% |
| 3. 팀과 보안 | 10주 (36주) | 팀 메모리와 용어집, 무보존 경로, SSO, 웹 관리 콘솔, 내보내기, 코칭. 유료 출시 | 유료 팀 10곳 |
| 4. 확장 | 12주 (48주) | 본인 목소리 음성 통역, 기밀 경로, 모바일 앱 | 3단계 지표를 보고 우선순위를 다시 정한다 |

## 성공 지표

목표값은 초기 가설이고 알파 데이터로 조정한다.

| 지표 | 목표 |
| --- | --- |
| 첫 자막까지 걸리는 시간 | 신규 사용자의 80%가 첫 실행 후 1분 안 |
| 주간 유지율 | 4주 차 40% |
| 답변 카드 사용률 | 표시된 카드의 25%가 발화나 복사로 이어짐 |
| 발언 비중 | 사용 4주 뒤 본인 발언 비중 상승 |
| 팀 확산 | 개인 가입 후 30일 안에 같은 회사 3인 이상 사용 |
| 회의 1시간당 변동비 | $0.5 이하 |

## 리스크

| 리스크 | 내용 | 대응 |
| --- | --- | --- |
| 수요 가정 | 혼합 언어 팀의 수요는 직접 증거가 없다 | 0단계 인터뷰 결과를 착수 조건으로 둔다 |
| 플랫폼 내장 기능 | Teams, Meet, Zoom이 번역과 음성 통역을 요금제에 넣고 있다 | 자막만으로 과금하지 않는다. 말하기, 내 맥락, 여러 플랫폼 지원에 투자한다 |
| Smooth의 대응 | 거의 매주 배포하는 팀이라 빠르게 따라올 수 있다 | 데이터 경로와 관리 기능처럼 구조를 바꿔야 하는 영역을 앞세운다 |
| 데스크톱 기술 선택 | GPUI는 1.0 이전이고 오버레이에 네이티브 보완이 필요하다 | 0단계에서 오버레이를 먼저 검증한다. [아키텍처](04-architecture.md) 참고 |
| 한국어 인식 품질 | 한국어 스트리밍과 한영 혼용의 독립 벤치마크가 없다 | 자체 평가 세트로 벤더를 비교한 뒤 확정한다 |
| 동의와 법규 | 참석자 동의 없는 전사와 음성 복제는 국가별 규제 대상이다 | 안내 문구 템플릿과 음성 등록 동의 절차를 넣고 법무 검토를 받는다 |
| 평판 | 답변 제안 오버레이는 부정행위 도구라는 낙인이 있다 | 숨김 기능을 만들지 않고 공개적인 사용을 전제로 설계한다 |

## 열린 질문

- 첫 타깃을 팀으로 둘지 개인으로 둘지
- 인력 가정(엔지니어 4명, 디자이너 1명)이 맞는지
- macOS를 먼저 내는 것이 타깃 팀의 기기 구성과 맞는지
- 음성과 대화록을 국내에 저장해야 하는 고객이 얼마나 되는지
